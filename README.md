# Incident Response Lab: Network Traffic Analysis & Host Attribution

This repository documents a step-by-step incident response investigation analyzing malicious network traffic from a packet capture (.pcap) file.

The Security Operations Center (SOC) identified outbound Command and Control (C2) traffic generated by NetSupport Manager RAT communicating with external IP 45.131.214.85. The goal of this investigation is host attribution: tracing the malicious network traffic back through the local network to identify the infected host machine, hardware interface, system hostname, active domain user account, and the user's real full name.

## Step-by-Step Investigation Walkthrough

### Step 1: Identify the Infected Host IP Address

#### Objective
Find the local network IP address within the 10.2.28.0/24 subnet that is actively communicating with the known malicious C2 IP server (45.131.214.85).

#### Wireshark Display Filter
Filter: 'ip.addr == 45.131.214.85'

#### Detailed Explanation
1. Open 2026-02-28-traffic-analysis-exercise.pcap in Wireshark.
2. Type 'ip.addr == 45.131.214.85' in the display filter bar at the top and press Enter.
3. Analyze the isolated packet conversations:
   - Source IP: 10.2.28.88 sends continuous HTTP POST requests targeting [http://45.131.214.85/fakeurl.htm](http://45.131.214.85/fakeurl.htm).
   - HTTP Payload Details: Inspecting the HTTP request headers reveals the User-Agent NetSupport Manager/1.3, confirming malicious RAT beaconing activity originating from 10.2.28.88.

#### Findings
- Infected Client IP Address: 10.2.28.88.


---

### Step 2: Extract the Physical MAC Address

#### Objective
Find the Media Access Control (MAC) address of the physical network interface card (NIC) belonging to the infected machine (10.2.28.88).

#### Wireshark Display Filter
 keep the filter from Step 1 applied: 'ip.addr == 45.131.214.85'

#### Detailed Explanation
1. Select any outbound packet where the Source is 10.2.28.88 (e.g., Frame 2640 or 2642).
2. In the lower-left Packet Details pane, expand the Ethernet II layer.
3. Inspect the Source MAC address field:
   - Source MAC: Intel_b2:4d:ad (00:19:d1:b2:4d:ad)
   - Destination MAC: Cisco_41:ae:25 (00:05:00:41:ae:25 — Default Gateway interface)

#### Alternative Verification Method
Filter by 'arp' and locate an ARP request originating from IP 10.2.28.88 asking for the gateway address. The sender MAC address field matches 00:19:d1:b2:4d:ad.

#### Findings
- Infected Client MAC Address: 00:19:d1:b2:4d:ad


---

### Step 3: Discover the Computer Hostname via DHCP

#### Objective
Extract the Windows workstation hostname assigned to the infected IP/MAC address using Dynamic Host Configuration Protocol (DHCP) lease traffic.

#### Wireshark Display Filter
Filter: 'dhcp'

#### Detailed Explanation
1. Clear the current filter bar, type 'dhcp', and press Enter.
2. Locate the DHCP Request packet (Frame 103) sent during network initialization.
3. Verify that the packet details match the infected client's MAC address (Client MAC address: Intel_b2:4d:ad / 00:19:d1:b2:4d:ad).
4. In the Packet Details pane, expand Dynamic Host Configuration Protocol > Option: (12) Host Name.
5. Read the plain-text string stored inside Host Name.

#### Findings
- Host Name String: DESKTOP-TEYQ2NR

---

### Step 4: Identify the Logged-In User Account Name via Kerberos

#### Objective
Identify the Active Directory domain user account logged into the infected system by inspecting Kerberos authentication requests.

#### Wireshark Display Filter
Filter: 'kerberos'

#### Detailed Explanation
1. Type 'kerberos' in the filter bar and press Enter.
2. Look for AS-REQ (Authentication Service Request) packets sent from the infected client IP (10.2.28.88) to the Active Directory Domain Controller (10.2.28.2).
3. Select an AS-REQ packet (e.g., Frame 251).
4. In the Packet Details pane, expand the following path:
   Kerberos > AS-REQ > req-body > cname > cname-string
5. Ignore entries ending with $(which represent machine accounts, e.g., DESKTOP-TEYQ2NR$).
6. Identify the human user account name stored in the CNameString field.

#### Findings
- User Account Name: brolf


---

### Step 5: Discover the User's Real Full Name via LDAP Directory Queries

#### Objective
Query the Active Directory responses captured in the PCAP to match the username brolf with the user's real full name.

#### Wireshark Display Filter
Filter: 'ldap'

#### Detailed Explanation
1. Type 'ldap' in the filter bar and press Enter.
2. Locate the LDAP search result entry packets (searchResEntry) returned by the Domain Controller (10.2.28.2) to the client (10.2.28.88).
3. Select an LDAP response packet (e.g., Frame 14965).
4. In the Packet Details pane, expand Lightweight Directory Access Protocol > searchResEntry > attributes.
5. Search through the attribute list or inspect the raw hex/ASCII packet pane on the right side for Active Directory user attributes such as serverName, dnsHostName...
6. Locate the full user profile details associated with domain account brolf.

#### Findings
- User Full Name: Becka Rolf
